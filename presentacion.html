⚠ El Problema

Las decisiones de IA logística son cajas negras

Cuando una IA de rutas genera una decisión crítica — desvío por clima, accidente, corte de ruta — no hay forma de auditar por qué tomó esa decisión. Los datos viven en servidores cerrados donde cualquiera puede alterarlos sin dejar rastro.

🔒

Plataformas cerradas

Los logs de IA se almacenan en bases de datos mutables, sin trazabilidad criptográfica.

🔍

Sin atribución

Imposible verificar quién creó cada registro o si fue modificado con posterioridad.

📋

Sin auditoría

Ante una falla operativa, no existe evidencia inmutable del razonamiento de la IA.

03 / 07
✅ La Solución

AeroTrack Sentinel

Un dashboard de auditoría logística que registra inmutablemente cada decisión de IA como entidades en Arkiv. Nadie puede alterar o eliminar un registro — cada decisión es verificable públicamente con un hash de transacción.

⛓️

Inmutable por diseño

Cada decisión se registra on-chain. El $creator garantiza la autoría sin posibilidad de manipulación.

🔢

Atributos numéricos

riskScore como atributo tipado permite filtrar por rango (riesgo > 5) directamente en la query.

🔗

txHash verificable

Cada operación genera un hash de transacción visible en el Block Explorer de Arkiv Braga.

🔑

Foreign key compartida

fleetId conecta flotas con decisiones, como una FK entre entidades Arkiv.

🏗️ Decisiones de Diseño

Por qué se configuró así

🏷️

PROJECT_ATTRIBUTE como namespace

Arkiv es una base compartida por todos los proyectos. Sin project: "aerotrack", una query devolvería entidades de otros equipos. Se estampa en toda creación y toda query como primer filtro.

🔢

Atributos number, no string

riskScore como number permite gt(5) correctamente. Como string, "10" < "5" por orden alfabético. Los atributos son índices; el payload es el contenido.

⏳

Expiración diferencia lógica de negocio

Flotas 30 días (datos duraderos) vs decisiones 24hs (una alerta de nieve pierde relevancia al día siguiente). La expiración no es un TTL técnico — modela la vida útil semántica del dato.

🔗

fleetId como FK compartida

Arkiv no tiene JOINs. Ambas entidades comparten fleetId como atributo, permitiendo eq("fleetId", "flota-01") para traer decisiones de una flota específica.

🔒

serializeWrite con retry + backoff

Transacciones simultáneas causan nonce races en testnet. serializeWrite encola writes secuencialmente y reintenta con backoff exponencial solo en errores retryable (429, nonce, red).

🔑

Backend wallet — sin MetaMask

El usuario nunca firma transacciones. La wallet server-side crea todas las entidades. $creator garantiza atribución inmutable. Blockchain 100% abstractada del usuario final.

🎬 Demo en vivo

Flujo de la demo

1

Clickear "Cargar datos de prueba" — 3 flotas + 8 decisiones se crean como transacciones en Arkiv

2

Clickear "Simular IA" — se genera una nueva decisión con riesgo aleatorio, visible en el dashboard

3

Click en el ícono de enlace junto a una entidad — se abre el Data Explorer con el payload y metadata

4

Cambiar el estado operativo de una flota — la transacción queda registrada on-chain con txHash

5

Filtrar solo alto riesgo (score > 5) — query con riskScore como atributo numérico

Cada acción produce un txHash verificable en Block Explorer
